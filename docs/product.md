# Forget Me Not — Product Definition

> 记录你买过的，也帮助下一位旅行者知道该在哪里买、多少钱。

---

## 1. Product Overview

### 1.1 Product Name

Forget Me Not

### 1.2 Product Type

Web App

### 1.3 Product Positioning

Forget Me Not 是一个以“旅行购物记录”为核心的 Web App。

它不是传统的旅行日记，也不是旅行照片相册，而是帮助用户记录旅行期间购买过的商品，并将：

- 商品
- 价格
- 货币
- 购买地点
- 购买日期
- 商品图片
- 商品分类

组织成结构化的旅行购物档案。

产品长期希望进一步发展为基于用户 UGC 的旅行购物价格与地点信息数据库。

---

## 2. Problem

### 2.1 Core Problem

用户旅行结束后，容易忘记：

- 买了什么
- 花了多少钱
- 在哪里买的
- 哪一天买的
- 当时买的商品是什么

现有记录方式通常是分散的。

### 2.2 Existing Solutions

用户目前可能使用：

- 手机相册
- 微信聊天
- 备忘录
- Excel
- 支付记录
- 社交平台收藏或笔记

### 2.3 Existing Solution Problems

这些方式通常无法同时建立：

> 商品 → 价格 → 地点 → 日期

之间的结构化关系。

支付记录更关注“花了多少钱”，
相册更关注“拍了什么”，
笔记更依赖用户手动组织。

Forget Me Not 的核心价值是建立以“商品”为中心的旅行购物记录。

---

## 3. Target Users

### 3.1 Primary Users

喜欢在旅行期间购物的年轻用户。

典型购物类型包括：

- 美妆
- 食品
- 服饰
- 饰品
- 日用品
- 电子产品
- 旅行纪念品

### 3.2 Phase 2 Users

Phase 2 及以后包括：

- 出行前查询价格的旅行者
- 希望分享旅行购物清单的用户
- 旅行购物类内容创作者 / 博主

---

## 4. Product Value

### 4.1 Phase 1 Core Value

帮助用户：

1. 快速记录旅行中买过的商品
2. 记录商品价格
3. 记录购买地点
4. 记录购买日期
5. 保存商品图片
6. 按旅行集中管理购买记录
7. 查看一次旅行的基本购买统计

### 4.2 Long-term Value

在用户积累大量公开记录后，逐步形成：

> 旅行 → 商品 → 价格 → 地点 → 时间

的结构化 UGC 数据。

未来可以帮助其他旅行者了解：

- 某商品在哪里可以买到
- 实际购买价格大约是多少
- 其他旅行者在哪里购买过
- 某个目的地的旅行者通常购买什么

# 5. Product Principles

## 5.1 Product Core

核心数据单元：

> 商品 × 价格 × 购买地点 × 日期 × 图片

## 5.2 Product Boundary

Forget Me Not 是：

> Travel Shopping Record

而不是：

> Travel Diary / Photo Album

普通旅行记录应该围绕“购买行为”展开，而不是围绕景点、酒店或旅行过程展开。

## 5.3 Recording First

Phase 1 优先验证：

> 用户是否愿意持续记录旅行购物。

Phase 2 在保留个人旅行购物记录核心的基础上，引入公开、搜索、推荐反馈、关注和购物代办。

## 5.4 Shopping Decision First

FMN 的公开内容、搜索、推荐和关注都服务于：

> 旅行购物决策

而不是发展为泛内容社区。

FMN 首先服务用户自己的旅行购物记录，再通过公开和分享服务其他旅行者。

## 5.5 Simple Recommendation

FMN 不采用以用户画像、浏览行为或内容消费行为为核心的大数据个性化推荐。

推荐内容主要基于用户对具体购物信息的：

> 推荐 / 不推荐

反馈。

推荐反馈用于表达：

> 这条真实购物信息是否值得其他旅行者参考。

不使用“点赞 / 收藏”作为核心产品机制。

- 1 张商品主图

## 6.4 Purchase Location

购买地点是商品记录的核心字段。

Phase 1：

- 使用用户手动输入的地点文本
- 可以提供简单的历史输入 / 自动补全体验
- 不使用地图
- 不使用 GPS
- 不接入地图 POI
- 不要求经纬度

---

## 6.5 Categories

Phase 1 使用以下商品分类：

- 美妆
- 食品
- 服饰
- 饰品
- 日用品
- 电子产品
- 其他

### Category Storage Mapping

数据库与 Seed Data 统一保存小写英文 slug。
UI 负责将 slug 映射为中文显示名称。分类语义不变。

| Slug (DB)     | UI Label |
| ------------- | -------- |
| `beauty`      | 美妆     |
| `food`        | 食品     |
| `fashion`     | 服饰     |
| `jewelry`     | 饰品     |
| `daily`       | 日用品   |
| `electronics` | 电子产品 |
| `other`       | 其他     |

---

## 6.6 Currency

用户可以为商品选择货币。

Phase 1：

- 支持当地货币记录
- 不进行实时汇率换算
- 不建立统一换算后的总金额

当一次旅行包含多种货币时，分别统计。

Example:

THB:
฿ 3,280

JPY:
¥ 12,400

# 10. Phase 1 UX Principles

### Recording

记录过程应该：

- 快速
- 清晰
- 低干扰
- 结构化

### Browsing

浏览旅行时：

- 商品图片优先
- 信息清晰
- 价格、地点、日期容易识别

### Data

统计信息：

- 简单
- 易读
- 不做复杂财务分析

### Feedback

- 成功 Toast
- 明确错误提示
- 删除前确认

# 12. Phase 2 — UGC / Public Travel Shopping Database

Status: Planned

Phase 2 在 Phase 1“记录自己的旅行购物”的基础上，引入用户账户、公开旅行、公开商品、搜索、推荐反馈、关注和购物代办。

Phase 2 的核心方向：

> 从“我的旅行购物记录”扩展到“旅行购物信息共享”。

产品仍然以真实旅行购物信息为核心。

其中：

> 商品真实购买价格与购买地点信息是 Phase 2 主功能。

> 目的地购物分享是主功能的自然延伸。

---

## 12.1 Phase 2 Goal

Phase 2 主要解决两类问题。

### 对分享者

用户已经完成一次旅行，并记录了：

- 买了什么
- 花了多少钱
- 在哪里买
- 什么时候买

这些真实购物记录可以公开给其他旅行者。

### 对计划旅行的用户

用户在出发前可能会遇到：

> 去某个目的地不知道可以买什么。

或者：

> 已经知道想买什么，但不知道当地大概多少钱、在哪里可以买。

因此 FMN 提供两种主要的信息获取方式：

### 商品导向

> 我要买这个东西 → 查询当地真实购买价格和购买地点

### 目的地导向

> 我要去这个地方 → 看别人实际买了什么，获得购物参考

---

## 12.2 Phase 2 Target Users

### 旅行购物分享者

希望记录并公开自己的旅行购物清单，让其他旅行者参考。

包括普通旅行者以及旅行购物类内容创作者 / 博主。

### 旅行计划用户

在出发前：

- 不知道买什么
- 想了解目的地可以买什么
- 想了解当地真实价格
- 想知道通常在哪里购买

---

支持：

- 用户名 / 名称

不设置：

- 我的点赞

## 12.5 Phase 2 Pages

### P1 — 我的旅行

登录后的核心个人工作台。

功能：

- 查看个人信息
- 编辑头像
- 编辑用户名 / 名称
- 编辑简介
- 查看关注数
- 查看粉丝数
- 创建旅行
- 查看自己的旅行档案
- 编辑旅行
- 删除旅行
- 进入旅行详情

旅行档案根据旅行状态进行区分：

- 即将出行
- 进行中
- 已结束

旅行状态属于同一个旅行档案的生命周期。

不创建两套“未出行旅行”和“已结束旅行”。

状态通过操作完成转换：

> 即将出行 → 进行中 → 已结束

其中具体状态名称可在正式设计阶段保持一致，不得创建重复旅行数据。

---

### P2 — 旅行详情

查看和管理某一次旅行。

功能：

- 查看旅行名称
- 查看旅行日期
- 查看旅行封面
- 查看旅行状态
- 查看公开 / 私密状态
- 查看购物记录
- 查看购物代办
- 添加购物记录
- 添加购物代办
- 编辑旅行
- 删除旅行

### 旅行信息编辑

旅行名称、旅行日期、旅行主图以及：

> 公开 / 私密

统一在旅行编辑窗口中管理。

旅行公开 / 私密不是独立页面。
旅行公开状态会约束所属商品的公开状态。

私密旅行中不能存在公开商品。
---

### P3 — 购物记录

表示：

> 已经购买的商品。

功能：

- 查看商品
- 添加商品
- 编辑商品
- 删除商品
- 查看价格
- 查看货币
- 查看购买地点
- 查看购买日期
- 查看图片
- 查看分类
- 设置公开 / 私密

商品公开 / 私密状态必须遵守所属旅行的公开状态规则：

- 公开旅行中的商品可以公开或私密
- 私密旅行中的商品只能私密

购物记录是 FMN 真实购买数据的核心来源。

---

### P4 — 购物代办

表示：

> 准备购买的商品。

功能：

- 查看待购买商品
- 手动新增代办
- 编辑代办
- 删除代办
- 查看参考价格
- 查看参考地点
- 查看来源
- 标记已购买

购物代办可以来自：

- 用户自己手动添加
- 其他用户公开的购物记录 / 商品信息

从公开商品加入购物代办时，应尽可能继承已有商品信息，避免用户重新填写。

### 核心转换

> 购物代办 → 已购买 → 购物记录

“已购买”是购物代办与购物记录之间的桥梁。

用户点击“已购买”后，不应要求重新完整填写一遍商品。

系统应继承已有的：

- 商品名称
- 商品图片
- 分类
- 参考价格
- 参考地点
- 来源信息

用户主要补充实际购买信息，例如：

- 实际价格
- 实际购买地点
- 实际购买日期
- 实际购买图片
- 备注

完成后形成正式购物记录。

---

### P5 — 商品详情

商品的统一详细信息页面。

#### 自己的商品

功能：

- 查看商品信息
- 编辑
- 删除
- 设置公开 / 私密
- 查看所属旅行

商品的公开 / 私密状态必须遵守所属旅行的公开状态规则：

- 公开旅行中的商品可以公开或私密
- 私密旅行中的商品只能私密

#### 别人的公开商品

功能：

- 查看商品名称
- 查看价格
- 查看货币
- 查看购买地点
- 查看购买日期
- 查看图片
- 查看所属旅行
- 查看作者
- 推荐
- 不推荐
- 加入购物代办

核心行为：

> 看到商品 → 认可其购物信息 → 加入购物代办

### P6 — 搜索

P6 与 P1 属于产品入口后的两个并行一级页面。

P6 不是 P1 的子页面。

P6 的核心作用：

> 发现和寻找旅行购物信息。

页面包含两个主要部分：

#### 公开内容推荐

搜索框下面展示公开旅行购物信息，包括：

- 公开旅行档案
- 公开购物记录

推荐内容不是无限滚动的信息流。

推荐主要依据公开购物信息获得的：

- 推荐反馈
- 不推荐反馈

进行朴素的信息排序与展示。

不使用：

- 用户画像推荐
- 浏览行为画像
- 内容消费行为推荐
- 复杂个性化推荐算法

#### 搜索入口

提供统一搜索入口。

搜索对象包括：

- 商品
- 目的地 / 旅行
- 用户

暂不建立国家导航分类。

## 12.6 Product Information Hierarchy

Phase 2 的信息价值存在明确主次关系。

### 主功能：商品真实购买信息

核心问题：

> 我想买这个东西，当地多少钱、在哪里可以买？

核心数据：

- 商品
- 价格
- 货币
- 购买地点
- 购买日期
- 商品图片
- 推荐 / 不推荐反馈

### 次功能：目的地购物分享

核心问题：

> 我要去这个地方，别人都买了什么？

主要参考：

- 公开旅行档案
- 旅行购物清单
- 公开商品
- 购买地点
- 实际购买价格

目的地购物分享服务于用户的旅行购物决策，不替代商品价格信息这一核心功能。

## 12.7 Search and Recommendation

### 商品搜索

商品搜索是 FMN Phase 2 的核心搜索场景。

例如用户搜索：

> 防晒

主要查看：

- 商品
- 真实购买价格
- 购买地点
- 购买日期
- 公开购买记录
- 推荐数
- 不推荐数

### 搜索结果排序

商品信息具有时间敏感性。

默认排序：

> 最新购买优先

同时允许用户主动选择简单排序：

- 最新购买
- 推荐数
- 价格

不建立隐藏的综合推荐分。

### 购买时间

购买日期必须作为商品公开信息的一部分保留。

原因：

> 三四年前的真实价格，即使获得很多推荐，也不能直接代表当前价格。

因此：

> 推荐反馈、购买时间、真实价格分别作为独立的信息维度。

### 目的地 / 旅行搜索

目的地搜索属于 Phase 2 的次级购物参考场景。

例如：

> 泰国

可以找到：

- 公开旅行档案
- 用户在该目的地购买过的商品
- 公开购物清单

进入：

> P7 公开旅行详情

再进入：

> P5 商品详情

最终可以：

> 加入购物代办。

### 用户搜索

搜索用户可以进入：

> P8 公开用户主页

用于继续查看该用户的公开旅行购物记录并决定是否关注。

## 12.8 Recommendation Model

FMN 不使用：

- 点赞
- 收藏
- 获赞

作为核心产品机制。

FMN 使用：

### 推荐

### 不推荐

两个用户反馈。

反馈针对：

> 具体公开购物信息。

展示真实数量，例如：

> 推荐 24

> 不推荐 3

不输出：

> 86% 推荐度

也不将其折算成单一“综合可信分”。

推荐反馈主要用于帮助其他旅行者判断：

> 这条真实购物信息是否具有参考价值。

### 旅行档案推荐程度

公开旅行档案可以基于其公开购物信息获得的推荐反馈形成整体认可程度展示。

旅行档案的整体推荐计算方式在进入实际开发前进一步确认。

不得由 AI 自行决定复杂评分公式。

## 12.9 Public / Private

Phase 2 支持：

### 旅行

- 公开
- 私密

### 商品

- 公开
- 私密

商品可以设置为公开或私密，但商品的公开状态受到所属旅行公开状态限制：

- 所属旅行为公开时，商品可以设置为公开，也可以设置为私密
- 所属旅行为私密时，商品只能设置为私密，不能单独公开

### 旅行公开状态变更

当公开旅行修改为私密旅行时，如果该旅行中存在公开商品，系统需要提示用户：

> 将旅行设为私密？

该旅行中有 2 个公开商品。

请选择：

- 将所有公开商品设为私密
- 取消

用户确认后：

- 当前旅行修改为私密
- 该旅行中的所有公开商品自动修改为私密

系统不得保留“私密旅行 + 公开商品”的状态。

公开内容可以参与：

- 搜索
- 推荐展示
- 分享
- 其他用户查看

私密内容只供内容所有者使用。

## 12.10 Follow

关注不是泛社交机制。

关注的产品意义是：

> 我认为这个人的旅行购物选择与我的需求或审美比较匹配，希望以后继续参考。

用户可以：

- 关注用户
- 取消关注
- 查看我的关注
- 查看我的粉丝

关注主要服务：

> 长期购物参考。

## 12.11 Shopping Todo

购物代办是 Phase 2 新增的核心功能之一。

购物代办表示：

> 我准备买什么。

购物记录表示：

> 我已经买到了什么。

购物代办不是普通收藏夹，也不是内容收藏功能。

### Shopping Todo Sources

购物代办可以来自：

- 用户手动新增
- 公开商品加入
- 公开旅行购物记录中的具体商品加入

### Add to Shopping Todo

用户看到一个公开商品后：

> 加入购物代办

然后选择：

- 加入已有旅行
- 新建旅行后加入

### Shopping Todo Lifecycle

> 购物代办 → 已购买 → 购物记录

用户不应为了完成转换而重新完整录入商品。

### Shopping Todo Information

购物代办可保留：

- 商品名称
- 参考价格
- 参考地点
- 来源
- 商品图片
- 商品分类
- 备注

实际购买后补充：

- 实际价格
- 实际购买地点
- 实际购买日期
- 实际购买图片
- 备注

## 12.12 Travel Status

旅行不是分成“未出行旅行”和“已结束旅行”两套数据。

同一个旅行档案通过状态完成生命周期。

主要状态：

- 即将出行
- 进行中
- 已结束

状态转换：

> 即将出行 → 进行中 → 已结束

状态转换不创建新的旅行档案。

旅行状态与购物代办共同形成：

> 计划 → 行动 → 真实记录

## 12.14 Core Interaction

Phase 2 的核心行为链：

### 旅行状态桥

```text
即将出行
   ↓
进行中
   ↓
已结束
````

同一旅行档案完成状态转换，不创建重复旅行。

### 商品状态桥

```text
购物代办
   ↓
已购买
   ↓
购物记录
```

已有代办信息应尽可能自动继承。

### 公共信息桥

```text
公开购物信息
      ↓
推荐 / 不推荐
      ↓
用户参考
      ↓
加入购物代办
      ↓
实际购买
      ↓
形成新的真实购物记录
      ↓
再次成为公开参考信息
```

## 12.16 Phase 2 Success Criteria

Phase 2 至少形成以下完整闭环：

> 用户记录 → 公开 → 被搜索 / 推荐 → 被其他用户参考 → 加入购物代办 → 实际购买 → 形成新的真实购买记录

同时：

> 商品真实购买价格仍然是 FMN 的第一核心信息。

目的地购物分享作为第二层价值存在。

关注作为长期购物参考关系存在。

推荐 / 不推荐作为公开购物信息的用户反馈存在。

购物代办作为从“看到想买”到“实际购买”的桥梁存在。

# 15. Product Success Criteria

## Phase 1

Phase 1 主要验证：

1. 用户能否顺利创建一次旅行
2. 用户能否快速记录购买商品
3. 用户能否完整记录商品的价格、地点、日期
4. 用户能否在旅行详情中快速找到购买记录
5. 用户能否查看商品详情
6. 用户能否编辑 / 删除错误记录
7. 用户是否愿意在真实旅行中持续使用

Phase 1 的核心不是功能数量，而是验证：

> 用户是否愿意把旅行中的购买行为记录下来。

## Phase 2

Phase 2 主要验证：

1. 用户能否注册 / 登录并建立自己的旅行购物档案
2. 用户能否正确设置旅行和商品的公开 / 私密状态，并遵守商品不能在私密旅行中独立公开的规则
3. 用户能否公开真实购物信息
4. 其他用户能否通过搜索找到商品价格与购买地点
5. 用户能否通过目的地搜索了解其他旅行者买了什么
6. 用户能否对公开购物信息进行推荐 / 不推荐反馈
7. 用户能否关注自己认可的旅行购物参考者
8. 用户能否将公开商品加入购物代办
9. 用户能否简单地将购物代办转为购物记录
10. 新的真实购物记录能否再次成为公开参考信息

Phase 2 的核心不是功能数量，而是验证：

> 用户是否会利用真实旅行购物信息进行出行前购物决策，并形成“公开参考 → 购物代办 → 实际购买 → 新记录”的循环。
